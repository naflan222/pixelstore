# 2026-09-01 Work Log

## Cart price display fix (previous session, carried over)
- Fixed stale demo prices (Rs. 38.84 on cart.html, Rs. 39.84 on checkout.html) by replacing `class="counter"` with `class="cart-total"` to avoid jquery.counterUp animation interference with dynamic cart totals.
- Updated `js/api-client.js` selectors from `.cart-amount-area .counter` to `.cart-amount-area .cart-total`.

## Add-to-cart "+" button fix
- **Problem**: "+" buttons on home.html, shop-grid.html, category pages, and related product sections had no `data-cart-id` attribute, so `bindProductButtons()` never wired them. Users had to go to the product detail page to add items.
- **Fix**: Added a generic handler in `bindProductButtons()` that matches `.product-card .btn-primary` buttons containing a `ti-plus` icon, extracts the product slug from the nearest `.product-title` link, and calls a new `/api/cart/by-slug` endpoint.
- Added `POST /cart/by-slug` route in `server/routes.js` that looks up product by slug and adds to cart.

## Product detail "Add to Cart" button fix
- **Problem**: `wireProductDetail()` was looking for `a[href="cart.html"]`, `.add-to-cart-btn`, or `.btn-danger.btn-lg` — none of which matched the actual `<form class="cart-form">` submit button.
- **Fix**: Updated `wireProductDetail()` to intercept the `.cart-form` submit event, read the quantity from `.cart-quantity-input`, and send it with the cart add request.

## Default quantity fix
- Changed `value="3"` to `value="1"` on all 17 product detail pages (3waystick, 27mstick, 3slotcharger, 19kit, 3mstick, 12in1kit, cover, domeport, fhstick, goggles, gbattery, gptemp, helmetstrap, lensfilter, x4case1, single-product, wpdcase).
