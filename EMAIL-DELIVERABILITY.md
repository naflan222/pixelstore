# Why your emails land in spam — and how to fix it

The store already sends well-formed email (multipart plain-text + HTML, consistent
branded `From:`, valid `Reply-To:`, calm subjects, no spam-bait wording). If the
password-reset OTP still arrives in spam, the cause is almost always **domain
authentication** — DNS records that prove *your server* is allowed to send *as your
domain*. No code change can replace this; every mailbox provider (Gmail, Outlook,
Yahoo) checks it before deciding where to put a message.

## 1. Golden rule: `From` must match the SMTP login

```
SMTP_USER = orders@yourdomain.com
MAIL_FROM = orders@yourdomain.com      ← same address
MAIL_FROM_NAME = PixelHouse
MAIL_REPLY_TO = support@yourdomain.com (optional)
```

Sending Gmail as `you@gmail.com` while `MAIL_FROM` says `hello@yourdomain.com` gets
the message rewritten or flagged as spoofing. The server now prints a console
warning when it detects this mismatch — check your logs.

**Using a plain `@gmail.com` address?** Then all three DNS records below already
exist (Google maintains them) and the fix is simpler: ask recipients to hit
*Report not spam* once, and keep sending only transactional mail. Gmail-to-Gmail
delivery normally lands in the inbox once the address has some positive history.

## 2. Custom domain? Add the three DNS records

Add these at your DNS provider (Cloudflare, Namecheap, GoDaddy, cPanel…). Values
for a domain `yourdomain.com` sending through Gmail SMTP:

| Record | Name | Value |
|---|---|---|
| SPF | `@` | `v=spf1 include:_spf.google.com ~all` |
| DMARC | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.com; adkim=s; aspf=s` |
| DKIM | `google._domainkey` | generated by Google — see below |

**DKIM** is the one most people miss and the one that matters most:

- **Google Workspace** (custom domain on Gmail): Admin console → Apps → Google
  Workspace → Gmail → *Authenticate email* → generate the DKIM key, then publish
  the `google._domainkey` TXT record and click *Start authentication*.
- **Other SMTP providers** (Brevo, SendGrid, Mailgun, Zoho…): their dashboard has
  a "Domains" page that gives you all three records to copy-paste, then verifies them.

Verify afterwards with [mail-tester.com](https://www.mail-tester.com) (send a test
to the address it shows you; aim for 10/10) or
[Google Admin Toolbox](https://toolbox.googleapps.com/apps/checkmx/).

## 3. If you send a custom domain *through* Gmail SMTP

In Gmail: ⚙️ → *See all settings* → *Accounts* → *Send mail as* → add
`orders@yourdomain.com` with your SMTP credentials, and answer **YES** to
"Treat as alias". Gmail will then sign your mail with your domain's DKIM instead
of `gmail.com`'s — this alone moves most messages out of spam.

## 4. Reputation habits (mailbox providers watch behaviour)

- **Warm up**: a brand-new address blasting 200 emails/day looks like spam. Keep
  volume low for the first weeks.
- **Only transactional mail**: OTPs and invoices are exactly what inboxes like.
  Never add marketing blasts to the same address.
- **Ask early customers** to add the sender to contacts / mark *Not spam* once —
  engagement is a direct ranking signal.
- **Avoid link shorteners** and long chains of links in emails.

## 5. Production-grade option: a transactional email provider

Gmail SMTP is fine to start, but for reliable delivery at volume use a provider
with proper DKIM signing, bounce handling and dashboards. All are drop-in
replacements — just change the env vars:

```
# Brevo (free tier: 300 emails/day)
SMTP_HOST=smtp-relay.brevo.com  SMTP_PORT=587  SMTP_USER=...  SMTP_PASS=...

# Resend, SendGrid, Mailgun, Amazon SES — same pattern
```

## What the code does for you already

- `From` = authenticated SMTP user + `MAIL_FROM_NAME` display name, with a console
  warning on mismatch (`server/mailer.js`)
- `Reply-To` set to a real inbox (`MAIL_REPLY_TO` or the SMTP user)
- Every email ships as **multipart/alternative** (plain text + HTML)
- Calm, specific subjects — no caps/exclamations/spam words
- Order confirmations include the invoice PDF attachment with a proper
  `application/pdf` content type
